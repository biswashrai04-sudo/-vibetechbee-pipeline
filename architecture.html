The 8 Pipeline Waves

Sequential waves · parallel agents within waves
0
Brand Setup
run once
Interactive onboarding — captures brand voice, tone per platform, visual style, content pillar ratios, competitors. Outputs BRAND_GUIDE.md read by all agents. If missing, agents degrade gracefully with built-in defaults (VibeTechBee brand).
social-brand-setup
Brand Strategist — 3-questions-at-a-time interactive Q&A via question tool
tool: question · output: BRAND_GUIDE.md
1
Trend Discovery
scan → score → select
Scans 7 niches across 5+ sources each. Scores by velocity × reach × engagement. Dedups against 7-day history.
social-trend-scanner
Scans X trending, Reddit, Google Trends, Product Hunt, TechCrunch, Google News across all 7 niches
webfetch · 7 niches · real-time
social-topic-selector
Picks best candidate: weighted scoring, dedup against calendar, day-of-week fit check
read · weighted scoring · dedup
2
Verification & Research
freshness → sentiment → fallback loop
Quality gate: checks publish dates <48hr, rejects negative topics. Max 3 retries before evergreen fallback. Deep researcher extracts facts, stats, quotes from 3+ sources.
social-freshness-verifier
Gate agent: checks dates, runs sentiment, auto-rejects, signals retry loop
webfetch · gate · sentiment · max 3 loops
social-evergreen-fallback
Safety net: generates from brand knowledge base when trend pipeline empties
fallback · edit
social-researcher
Deep dive: extracts facts/stats/quotes, runs competitor differentiation analysis
webfetch · 3+ sources · competitor scan
3
Strategy — The Brain
Stage A → B · fresh context each stage
Stage A: reads research + brand guide + last 3 calendar entries, assigns angles/tone/format per platform, writes core message. Stage B: fresh read, picks hooks/CTAs/tactics/keywords/timing.
social-strategist — Stage A
Strategy Matrix: platform angles, tone, format, core message statement, yesterday check
read · fresh context · core message · yesterday check
social-strategist — Stage B
Tactical Brief: hook formulas, CTAs, engagement tactics, keywords, visual direction, timing
edit · hook library · platform signals · engagement tactics
4
Content Writing
4 agents · parallel
All writers read STRATEGY_TACTICAL.md. Each writes to their platform's #1 engagement signal. Character audit on X. Trigger word check on Facebook. Alt text on all images.
social-instagram-writer
Carousel caption (125-150 words) + 5 hashtags + slide text + story hook. CTA → DM SHARES
edit · carousel · alt text
social-linkedin-writer
Thought leadership structure: Hook (1-2 lines) → Context (2-3 sentences) → Insight (3-5 bullets) → CTA (1 sentence). 800-1200 chars. CTA → DWELL TIME
edit · hook/insight/CTA structure
social-x-writer
Tweet or thread (3-7 tweets). Appends ## Character Audit footer: counts total chars + each tweet. Must stay ≤280 per tweet. CTA → REPLIES
edit · 280 limit · ## Character Audit
social-facebook-writer
Community discussion ~300 chars, trigger word check. CTA → MEANINGFUL INTERACTIONS
edit · trigger word check
5
Image Generation
Flux.2 Max via OpenRouter
Generates 1 image per platform (4 total). Calls OpenRouter API: POST to https://openrouter.ai/api/v1/chat/completions with model chain. Reads OPENROUTER_API_KEY from .env. Per-platform dimensions: IG 1080×1350, LI 1200×627, X 1500×500, FB 1200×630. Brand style from BRAND_GUIDE.md. Alt text per image. Fallback chain: black-forest-labs/flux.2-max → flux.1.1-pro → flux-schnell → IMAGE_PROMPTS.md if all exhausted.
social-image-gen
Visual Creator — flux.2-max → 1.1-pro → schnell → text fallback
webfetch · flux.2-max · 1.1-pro · schnell · prompts fallback
6
Package & Deliver
organize → checklist → calendar
Organizes all outputs into date folder. Cross-checks all 4 posts against CORE_MESSAGE for contradictions. Creates CHECKLIST.md with 1-line previews, optimal posting order (LI 8:30AM → X 9AM → IG 11AM → FB 7PM). Updates CONTENT_CALENDAR.md.
social-packager
Delivery Manager — organizes, previews, checks, logs
edit · posting order · preview · calendar update
7
Human Approval Gate
you decide
No agent. You review CHECKLIST.md and approve via /social-approve or publish manually. Nothing auto-posts.

How opencode Executes the Pipeline

Command → Skill → Subagents → Output
1

You type a command

/social-post daily — opencode loads the matching command file from commands/social-post-daily.md

2

Command loads the skill

The command instructs opencode to load social-posting.skill.md which contains the full pipeline orchestration logic — wave sequencing, agent spawning rules, retry logic, and output structure.

3

Skill orchestrates waves

The skill uses the task() tool to spawn subagents per wave. Sequential waves (1→2→3...) but parallel agents within a wave (e.g., Wave 4 spawns 4 writers simultaneously). Each subagent reads its agent .md file for instructions.

4

Agents execute & write files

Each agent reads context (STRATEGY.md, BRAND_GUIDE.md), executes its task using tools like webfetch (scanning) and edit (writing output), then writes its result to ./social-posts/YYYY-MM-DD-topic/

5

You review & approve

Packager creates CHECKLIST.md with all 4 post previews and optimal posting order. You review, optionally use /social-approve to log, then copy-paste to platforms.

10 Gap Fixes Applied

From virtual test → resolved in v1.0
1. Strategist context overload
Split into Stage A + B with fresh context per stage
2. No yesterday-awareness
Strategist reads last 3 calendar entries before deciding
3. No negative topic detection
Sentiment scan added to freshness verifier
4. No evergreen fallback
Dedicated fallback agent when trend pipeline empties
5. No core message enforcement
CORE_MESSAGE — all writers must obey, prevents contradiction
6. No content pillar ratios
40/30/20/10 split defined in BRAND_GUIDE.md
7. No posting order
Time-optimal order per platform in CHECKLIST.md
8. No character count for X
280-char hard limit + ## Character Audit self-check
9. No image alt text
Image gen outputs alt text per image
10. No feedback loop
Documented as V2 — performance review agent
